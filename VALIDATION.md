# Проверка Cowabunga Jellyfin Companion

## Версия 1.0.15

Исправлены две причины ложных обновлений для Kodi Sync Queue: каждый проход индекса возвращал в очередь все совпадения, а совпадение SHA-256 всё равно вызывало UpdateItemAsync(ImageUpdate). Теперь обычный проход использует ChangedImageTypes, включая новые элементы при прежней ревизии облака. Полная перепроверка запускается после сохранения настроек и раз в сутки для восстановления перезаписанных файлов. Её отметка и подпись настроек сохраняются вместе с очередью; перезапуск сам по себе не возвращает все совпадения в очередь. Настройки медиатек, коллекций, типов изображений, режима хранения и разрешений замены учитываются.

Совпавший облачный файл проверяется по ссылке в базе через GetItemList(ItemIds), который обходит кэш GetItemById. Если путь уже сохранён, UpdateItemAsync не вызывается. Старые ссылки, оставшиеся только в памяти, исправляются при необходимости, независимо от прежних записей Managed. Равенство содержимого также проверяется для скачанного изображения резервного провайдера до SaveImage, чтобы повторное применение языковых настроек не пересохраняло ту же картинку.

300 тестов прошли. Новые проверки охватывают повторные проходы индекса, старые задания и перезапуск очереди; новые SHA-256; коллекцию, созданную после подтверждения индекса без смены ревизии облака; включение ролей и медиатек; однократный ремонт неперсистированной ссылки; ежедневное восстановление изменившегося файла; отсутствие записи для равного изображения от резервного провайдера. Остальные проверки сохранения, защиты ручных изменений и хранения файлов проходят. JavaScript четырёх страниц настроек проверен.

На настоящем **Jellyfin 12.2.0**, официальный образ `jellyfin/jellyfin:12.2`, digest `sha256:357724bf0ae27a672c7cbaa899db2d9abeb13dbd8657ccce750258a4c059d037`, ошибка воспроизведена с опубликованной DLL 1.0.14: повторный проход неизменного индекса создавал два события ItemUpdated с причиной ImageUpdate для тестовой коллекции. События считались отдельным временным наблюдателем, подписанным на ILibraryManager.ItemUpdated, в изолированном тестовом контейнере. Kodi отдельно не устанавливался.

После установки DLL 1.0.15 в ту же тестовую базу три повторных прохода дали **0 событий ImageUpdate**, очередь оставалась пустой. Новая коллекция получила оба облачных изображения; зарегистрированы два реальных обновления. Ещё два прохода не создали событий для неё. Использованы настоящие облачные изображения; облачный сервис не изменялся. Изменение облачных SHA-256 проверено автоматическим тестом с управляемым HTTP-источником. Рабочий сервер пользователя не изменялся; наблюдатель событий, журналы и тестовые данные не входят в релиз.

## Версия 1.0.14

Удалены запрос перевода студий к Wikidata (P11806), поле EnableRussianStudios, его импорт и элементы страницы настроек. Названия студий теперь сохраняются непосредственно из production_companies TMDB. Локализация людей и текстовый fallback остаются независимыми от студий.

291 тест прошёл. Проверки удалённого запроса заменены проверками сохранения студий TMDB без обращений к P11806 при включённых и выключенных русских именах людей. При отключённых именах и уже имеющемся русском тексте запросов к Wikidata нет; при включённых именах запрос P4985 сохраняется. JavaScript четырёх страниц настроек проверен.

На тестовом Jellyfin 12.1.0 версия 1.0.14.0 загрузилась с XML-конфигурацией предыдущей версии; устаревшая настройка отсутствует в API. Обновление Space Jam сохранило «Космический Джем», 1996 год и студии «Warner Bros. Family Entertainment», «Ivan Reitman Productions» при отключённой локализации людей. Рабочий сервер пользователя не изменялся. Уже сохранённые переводы студий в существующих карточках могут сохраняться до обновления метаданных с заменой.

## Версия 1.0.13

По журналу пользователя установлен сбой при получении русских названий студий из Wikidata (`FetchRussianLabelsByExternalIds`, свойство P11806): HTTP-тайм-аут в 30 секунд выбрасывал TaskCanceledException, который исключался из обработки ошибок и прерывал всё обновление фильма. Запрос TMDB перед этим успешно возвращал русские названия Space Jam и Mrs. Doubtfire. Исправление отличает отмену обновления через переданный CancellationToken от тайм-аута отдельного запроса. Тот же шаблон обработки исправлен в остальных провайдерах метаданных и изображений. Дополнительная локализация людей при ошибке сохраняет исходные TMDB-имена, роли и ID.

291 тест прошёл. Новые проверки воспроизводили 5 отказов до исправления: тайм-ауты переводов студий, актёров и текстового fallback, ненужный fallback при полном русском тексте и сохранение неправильного года после обновления. После исправления эти сценарии проходят; настоящая отмена обновления по-прежнему распространяется вызывающему коду, заблокированная карточка не меняется. Проверена JavaScript-синтаксическая корректность четырёх страниц настроек.

На настоящем **Jellyfin 12.1.0** из официального образа `jellyfin/jellyfin:12.1` (digest `sha256:78d3ea1207d1322471fcac39a614f004f2ccf7e878f95ab2977d752f07e4dd7e`) в отдельном контейнере с копией тестовой базы 12.0 проверены:

- Загрузка DLL версии 1.0.13.0, обнаружение провайдеров и запрет доступа к административным API без авторизации.
- Ручное распознавание и сохранение: **Космический Джем (1996)**, **Робокоп (1987)**, **Миссис Даутфайр (1993)**. Проверены русские названия и описания, TMDB ID, годы и списки участников. Для Space Jam предварительно сохранён ошибочный год 2026. Результаты сохранены после перезапуска сервера.
- Во время этой проверки реальные запросы Wikidata также завершались тайм-аутом; основные метаданные всё равно сохранялись. Полное обновление каждой тестовой карточки заняло около минуты: исправление устраняет отказ, но не гарантирует быстрый ответ внешнего сервиса.
- Распознавание вложенных сериалов и эпизодов, числового названия фильма и двух версий файла; исключённая медиатека и отключение модуля без перезапуска.
- Объединение связей актёра из фильма и сериала по одинаковым внешним ID с сохранением ролей.
- Фоновая замена существующих постера и лого коллекции облачными изображениями в режиме MediaFolder и сохранение результата после штатного FullRefresh при отключённом модуле обложек.

Сборка по-прежнему использует Jellyfin.Controller / Jellyfin.Model 12.0.0 и минимальный targetAbi 12.0.0.0. Изменения API между официальными v12.0 и v12.1 проверены для задействованных интерфейсов. Это проверка указанных сценариев на тестовом сервере; рабочий сервер пользователя не изменялся, его журнал и тестовые учётные данные не включены в репозиторий или архив.

## Версия 1.0.12

Исправлено вытеснение ожидающих заданий при повторной постановке всех совпадений индекса. Тест реального обработчика очереди на прежней логике воспроизвёл пропуск конца очереди: после обработки первых 50 записей повторная постановка занимала освобождённые слоты Dictionary, и следующий пакет снова выбирал их. Теперь используется сохраняемый QueueOrder; дубликат не меняет порядок или задержку повтора, новая проверка завершённой записи добавляется в конец. Очередь старого формата автоматически получает порядок при загрузке.

Для режима хранения рядом с видео исключены дублирующие задания Artwork для фильмов, сериалов и сезонов, которыми занимается ArtworkMediaWriter. Старые дубли удаляются из очереди без чтения изображений, изменения файлов и записей владения. Задания коллекций и языкового подбора сохраняются. Диагностика показывает активную работу, ожидание общего семафора и число обработанных заданий; чтение хешей не блокирует запись изображения. Журнал постановки считает только действительно добавленные позиции.

282 теста прошли, включая модель очереди из 3306 заданий (3304 делегированных файла и два изображения коллекции), отсутствие обращения к облаку для делегированного задания, сохранение порядка и задержки повтора после перезапуска. На настоящем Jellyfin 12 загружена очередь старого формата для 7 элементов медиатеки и коллекции: дубли убраны, оба изображения коллекции заменены фоновым обработчиком, хеши совпали с облаком, очередь опустела. Рабочий сервер пользователя не изменялся; его файлы диагностики не включены в репозиторий.

## Версия 1.0.11

278 тестов прошли. На Jellyfin 12 воспроизведено отсутствие Custom Artwork у новой коллекции, созданной после построения свежего индекса: до следующего перестроения 0 кандидатов, после — 2. Теперь новая коллекция сопоставляется с уже загруженным облачным каталогом без HTTP-запроса и полного пересчёта медиатеки; живой сценарий сразу возвращает оба изображения. Тест подтверждает сохранение ограничений модулей.

В Custom Artwork добавлена проверка коллекции по названию/TMDB ID с отчётом: активная версия, настройки, блокировки, текущие/облачные хеши, пути файлов, состояние очереди. Проверка не запускает замену. На настоящем Jellyfin проверены поиск коллекции, отчёт о блокировке и отказ в доступе без авторизации. JavaScript всех страниц проверен. Причина сообщения пользователя о пропуске после ручного обновления индекса на его сервере ещё не установлена; новая диагностика предназначена для получения этих данных.

## Версия 1.0.10

На настоящем Jellyfin 12 воспроизведён откат в версии 1.0.9: фоновая замена коллекции записывает изображения в metadata/library, но сохраняет прежние folder.jpg и logo.jpg в data/collections. После обычного FullRefresh без replaceAllImages Jellyfin снова выбирает старые файлы. Исправление сохраняет изображения штатным способом в служебной папке коллекции; устаревшие альтернативные имена переносятся в collection-image-backups после успешной записи. Папки коллекций вне data/collections не переводятся на этот способ записи, защитные настройки остаются в силе.

276 тестов прошли. Добавлены проверки постера и лого, миграции уже совпадающего облачного файла из metadata/library, сохранения резервных альтернатив и фона, защиты файлов без разрешения замены и границ папки data/collections. На тестовом Jellyfin после исправления постер и лого «Расплаты» совпали с облачными SHA-256 из предоставленного индекса и сохранили пути и теги после полного обновления метаданных/изображений при отключённом Companion. Это исключает повторное наложение плагином, маскирующее откат. Рабочий сервер пользователя не изменялся.

## Версия 1.0.8

268 тестов прошли. Ошибка из журнала пользователя `UNIQUE constraint failed: Peoples.Id` воспроизведена на Jellyfin 12 с версией 1.0.7: помимо Tom Hardy в актёрском списке присутствует неизменяемая запись с кириллическим именем. Старые внутренние ID неизменённых записей передавались обратно в UpdatePeopleAsync; SQLite-сопоставление имени могло инициировать повторную вставку этого ID. Исправление создаёт новые PersonInfo для всего записываемого списка с сохранением имён, ролей, порядка, ImageUrl и ProviderIds. Журнал пользователя в репозиторий не включён.

На исправленной сборке 1.0.8 тот же сценарий на настоящем Jellyfin 12 завершился со статусом Completed: фильм и сериал ссылаются на одну русскую карточку актёра, роли и неизменённый актёр сохранены, прежняя карточка остаётся доступной.

- Фильм `2012 (2009)` с двумя файлами версий 1080p/2160p после реального сканирования представлен одной карточкой с двумя источниками. Числовое название сохранено.
- Исключённая медиатека не появляется в истории действий Resolver. Выключение Resolver без перезапуска прекращает его действия при повторном сканировании.
- Веб-интерфейс Jellyfin: загрузка главной страницы, восстановление выбранных медиатек, сохранение настроек, переходы на страницы Resolver, Metadata и Artwork, обнаружение встроенного ключа TMDB.

## Отдельные сценарии автоматических тестов

- Все восемь сочетаний трёх модулей и главный выключатель.
- ID медиатеки после переименования, вложенные и одинаковые корни, границы пути, коллекции с отдельной областью действия.
- Повторный вход в проверку области действия при построении корня Jellyfin без рекурсии.
- Очередь изображений: объединение дубликатов, сохранение между перезапусками, ограниченный рост интервала повторов.
- Отключение модуля/медиатеки после постановки в очередь и после начала загрузки.
- Приоритет Custom Artwork над языковым подбором; ошибка облака не запускает замену из другого источника.
- Сохранение текущего файла при ошибке скачивания; защита ручной замены по хешу.
- Учёт загрузок штатным конвейером Jellyfin; проверка SHA-256 кастомного файла; перенос прежнего учёта изображений без перезаписи ручных замен.
- XML-конфигурация с русским текстом и независимыми параметрами модулей; импорт старого выключателя Resolver не выключает весь Companion.

## Границы проверки

Рабочий сервер и реальные медиатеки пользователя не изменялись. Сетевые сценарии выбора/записи изображений проверены детерминированными ответами HTTP; облачный индекс дополнительно успешно читался в тестовом сервере, но полное обновление пользовательской коллекции через внешние TMDB/Fanart/Wikidata не проводилось. Полная миграция с установленными тремя плагинами на рабочей базе не выполнялась.

Тесты выполнялись в Linux-контейнере на Windows-хосте. CI для Windows, Linux и macOS добавлен, но удалённые CI-задания ещё не запускались. Поддержка будущих версий Jellyfin требует отдельной проверки.
